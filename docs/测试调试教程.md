# 康复运动 App — 测试与调试小白教程

> 面向**没有 Flutter 经验**的使用者。每一步都给出完整命令，复制粘贴即可执行。
> 建议按顺序做，每做完一步对照"预期结果"确认成功再进入下一步。

---

## 第 0 步：认识两个东西

这个项目分成**两半**，必须**先启动后端，再启动前端**：

```
┌──────────────┐         ┌──────────────┐
│   后端 API    │ ◄────── │  前端界面     │
│  (NestJS)    │  网络请求 │  (Flutter)   │
│  端口 3000   │ ──────► │              │
└──────────────┘  返回结果 └──────────────┘
```

| 名称 | 作用 | 位置 | 启动后地址 |
|---|---|---|---|
| **后端 API** | 安全筛查、追问逻辑、调用 AI | `apps\api` | `http://localhost:3000` |
| **前端界面** | 你看到的手机/网页画面 | `apps\mobile` | 网页版 `http://localhost:8080` |

> **为什么必须后端先启动？**
> 前端只是个"壳"，所有判断（比如识别"胸痛"要报警）都在后端。
> 后端没启动，前端会显示"网络暂不可用"。

看到 `"status":"ok"` 就说明后端正常。

## 第 3 步：用命令行测试安全闸门（最重要）

这一步**不需要任何界面**，是验证"安全功能有没有生效"最快的方法。
在新 PowerShell 窗口里依次执行下面 3 条命令：

### 测试 ①：说"胸痛" → 应该报警

```powershell
curl -X POST http://localhost:3000/ai/chat -H "Content-Type: application/json" -d '{"message":"我刚才练着练着胸痛，还有点向左肩放射"}'
```

**预期结果**（关键看这三处）：

```json
{
  "type": "urgent",                    ← ① 类型是 urgent（紧急）
  "severity": 3,                       ← ② 严重度 3（最高）
  "modelCalled": false,                ← ③ 没调用 AI（安全！）
  "message": "🚨 立即就医提示..."
}
```

> ✅ **看到 `"modelCalled": false` 就对了** —— 说明遇到危险情况时，系统根本不会去问 AI，直接给固定安全提示。

### 测试 ②：正常提问 → 应该追问

```powershell
curl -X POST http://localhost:3000/ai/chat -H "Content-Type: application/json" -d '{"message":"脑卒中后想了解上肢摆放"}'
```

**预期结果**：

```json
{
  "type": "clarify",                   ← 类型是 clarify（需要追问）
  "questions": [{
    "slot": "stage",
    "question": "请问当前处于什么阶段？",
    "options": [
      { "label": "2 周内或术后早期", "value": "acute" },
      { "label": "1-3 个月恢复中", "value": "subacute" },
      { "label": "3 个月以上", "value": "chronic" },
      { "label": "不清楚", "value": "unknown" }
    ]
  }]
}
```

看到 `questions` 和 4 个选项就对了。

### 测试 ③：说"没有胸痛" → 不应该报警

```powershell
curl -X POST http://localhost:3000/ai/chat -H "Content-Type: application/json" -d '{"message":"我最近没有胸痛，就是膝盖有点酸"}'
```

**预期结果**：

```json
{ "type": "clarify", ... }     ← 是 clarify，不是 urgent
```

> ✅ 这条验证"否定句识别"。如果说"没有胸痛"也被报警，说明程序有问题。

### 三个测试对照表

| 输入 | 期望 `type` | 期望 `modelCalled` | 说明 |
|---|---|---|---|
| 胸痛、呼吸困难、突发无力 | `urgent` | `false` | 危险，立即就医，不问 AI |
| 正常提问 | `clarify` | `false` | 信息不全，先追问 |
| "没有胸痛" | `clarify` | `false` | 否定句不误报 |
| 急性期（stage=acute） | `urgent` | `false` | 急性期不给运动建议 |

## 第 4 步：启动前端界面

### 4.1 先选一条路线

| 方式 | 需要什么 | 首次耗时 | 推荐度 |
|---|---|---|---|
| **A. 网页版** | Chrome（已装 ✅） | 下载 ~100MB Web SDK | ⭐⭐⭐ **先试这个** |
| **B. 安卓真机** | 安卓手机 + 数据线 | 几乎不用下载 | ⭐⭐⭐ **最可靠** |
| **C. 安卓模拟器** | Android Studio 里创建 | 下载系统镜像 ~1GB | ⭐ 前两条都不行时 |

> **怎么选**：有安卓手机 → 直接走 B；没有 → 先试 A；A 网络不通 → 走 C。

### 方式 A：网页版

**新开一个 PowerShell 窗口**：

```powershell
cd D:\AI\R\rehab-motion-mvp\apps\mobile
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:3000
```

**首次运行会做什么**：

1. 下载 Flutter Web SDK（约 100MB，需要 1-5 分钟，看网速）
2. 编译项目（1-3 分钟）
3. 自动打开 Chrome 浏览器，显示 App 界面

**预期结果**：Chrome 打开，看到标题"康复运动 · AI 问答"，顶部橙色安全提示条。

> ⚠️ 如果卡在下载或报网络错误，见本文最后"常见问题 Q3"。

### 方式 B：安卓真机

1. 手机打开「设置 → 关于手机」，连点「版本号」7 次开启开发者模式
2. 设置里找到「USB 调试」，打开
3. 数据线连电脑，手机上点「允许 USB 调试」
4. 电脑执行：

```powershell
cd D:\AI\R\rehab-motion-mvp\apps\mobile
flutter devices
```

看到你的手机型号就说明连接成功。然后（把 `192.168.1.100` 换成你电脑的局域网 IP）：

```powershell
flutter run --dart-define=API_BASE_URL=http://192.168.1.100:3000
```

> 查电脑 IP：`ipconfig`，找「IPv4 地址」那一行。
> ⚠️ 真机**不能**用 `localhost`，必须用电脑的局域网 IP，否则连不上后端。

### 方式 C：安卓模拟器（前两条都不行时）

本项目**尚未创建过模拟器**，需要先在 Android Studio 里建一个：

1. 打开 Android Studio（`C:\Program Files\Android\Android Studio`）
2. 右侧或顶部菜单找 **Device Manager**（设备管理器）图标
3. 点 **Create Device** → 选任意一款手机（如 Pixel 7）→ Next
4. 选一个系统镜像下载（推荐 **API 34**，文件较大，需等待）
5. 下载完点 Finish，然后点 ▶️ 启动模拟器
6. 模拟器出现手机画面后，执行：

```powershell
cd D:\AI\R\rehab-motion-mvp\apps\mobile
flutter devices
```

看到 `sdk gphone` 或 `emulator-5554` 就说明识别到了。然后：

```powershell
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3000
```

> 💡 模拟器访问电脑本机要用特殊地址 `10.0.2.2`（不是 localhost，也不是电脑 IP）。

## 第 7 步：怎么调试

### 7.1 看后端日志

运行 `npm run start` 的那个窗口，会实时打印每个请求：

```
[Nest] 12345  - LOG [RoutesResolver] ChatController {/ai}:
```

> **看不到报错？** 后端窗口如果一片空白，说明请求根本没到后端——
> 检查前端的 `API_BASE_URL` 对不对，或者后端是不是被关了。

### 7.2 看浏览器控制台（网页版最强调试手段）

网页版运行后，在 Chrome 里按 **`F12`**，会打开开发者工具：

| 标签页 | 看什么 |
|---|---|
| **Console** | 红色错误信息、`print()` 输出 |
| **Network** | 每个网络请求。点 `/ai/chat` 能看到**请求内容**和**服务器返回** |
| **Sources** | 打断点单步调试 |

> 💡 **最常用的是 Network**：
> 点 Network → 找到 `chat` 请求 → 点开 → 看 `Response` 标签，
> 就能看到后端到底返回了什么 JSON。界面显示不对时，先看这里。

### 7.3 Flutter 里加打印

在代码里加：

```dart
print('调试：用户输入了 $message');
```

然后：

- 网页版：看浏览器 F12 的 Console
- 命令行：看 `flutter run` 那个窗口

## 常见问题对照表

### Q1. `flutter: command not found`（命令找不到）

**原因**：Flutter 没加入系统 PATH。

**解决**：用完整路径代替 `flutter`：

```powershell
D:\dev\flutter\bin\flutter.bat run -d chrome
```

或者把 `D:\dev\flutter\bin` 加到系统 PATH（搜索"编辑系统环境变量"）。

---

### Q2. 前端显示"网络暂不可用"

**排查顺序**：

1. 后端窗口还在吗？有没有显示 `successfully started`？
2. 新开窗口执行 `curl http://localhost:3000/health`，通不通？
3. 前端的 `API_BASE_URL` 对不对？
   - 网页版 / 模拟器：`http://localhost:3000`
   - 真机：`http://<电脑IP>:3000`（**不能**用 localhost）

---

### Q3. Web 构建卡住 / 报网络错误

**现象**：
```
Failed to download .../flutter-web-sdk.zip
HttpException: Proxy failed to establish tunnel (502 Bad Gateway)
```

**原因**：首次 Web 运行要下载约 100MB 的 Web SDK，网络不通或代理拦截。

**解决**（按顺序试）：

1. 再执行一次同样的命令（有时是偶发失败，值得重试 2-3 次）
2. 关掉 VPN / 代理软件再试
3. 手动设置 Flutter 国内镜像（**国内网络最有效**），
   在 PowerShell 里先执行这两行，再重新运行：

```powershell
$env:PUB_HOSTED_URL="https://pub.flutter-io.cn"
$env:FLUTTER_STORAGE_BASE_URL="https://storage.flutter-io.cn"
cd D:\AI\R\rehab-motion-mvp\apps\mobile
flutter run -d chrome
```

4. 换个网络（比如手机热点）
5. 实在不行 → 改用**方式 B 安卓真机**，不需要 Web SDK，最可靠

> 💡 第 3 步的镜像地址只在当前窗口有效，换窗口要重新执行。
> 想永久生效：搜索"编辑系统环境变量"，新建两个用户变量。

---

### Q4. `flutter devices` 看不到设备

**网页版**：确认 Chrome 已安装。本项目已添加 Web 支持（`web\` 目录存在）。

**安卓真机**：
1. 手机「USB 调试」开了吗？
2. 数据线能传文件吗？（有些线只能充电）
3. 手机上点了「允许 USB 调试」吗？
4. 执行 `flutter doctor` 看提示

---

### Q5. 改了代码但界面没变

1. 在 `flutter run` 窗口按 **`r`**（热重载）
2. 没反应就按 **`R`**（完全重启）
3. 还不行就 `q` 退出，重新执行 `flutter run`

---

### Q6. 后端启动报数据库连接错误

**现象**：
```
ERROR [TypeOrmModule] Unable to connect to the database
```

**说明**：这是**正常的**！本项目 P0 安全闸门**不依赖数据库**，
即使报这个错，`/ai/chat` 依然能正常工作（已验证）。

需要查动作库（`/exercises`）时才需要 Docker 启动 PostgreSQL，
当前 Docker 环境待修复，不影响安全功能测试。
