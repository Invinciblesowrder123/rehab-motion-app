
**首次启动**会编译 TypeScript（约 20-40 秒），出现下面这行才算成功：

```
[Nest] 12345  - LOG [NestApplication] Nest application successfully started
```

> `start:dev` 是**热重载模式**，改代码后自动重启。
> 想跑一次性版本：先 `npm run build`，再 `npm start`。
>
> **这个窗口不要关**，关了后端就停了。

### 可能的报错

| 报错 | 原因 / 处理 |
|---|---|
| `npm : 无法加载文件...禁止运行脚本` | PowerShell 执行策略限制。改用 `npm.cmd run start:dev` |

## 1.2 确认后端活着

**新开一个 PowerShell 窗口**（原来的不要关）：

```powershell
Invoke-RestMethod -Uri http://localhost:3000/health | ConvertTo-Json
```

**预期结果**：

```json
{"status":"ok","service":"rehab-motion-api","safetyGate":"enabled","disclaimer":"本服务不提供医疗诊断，所有建议仅供参考。"}
```

看到 `"status":"ok"` 就说明后端正常。

> 💡 为什么不用 `curl`：PowerShell 里 `curl` 是 `Invoke-WebRequest` 的**别名**，
> 执行它会返回一堆表格（`StatusCode` / `Content` …），而不是上面这行 JSON，容易看懵。

## 1.3 三条 HTTP 测试（核心）

### ⚠️ Windows 必读：两个坑都在"发送端"

1. **别用 `curl -d '{"message":"..."}'`**
   PowerShell 的 `curl` 是 `Invoke-WebRequest` 别名，不认 `-H` / `-d`；
   就算改成 `curl.exe`，PowerShell 也会篡改内联 JSON 的双引号，服务器收到非法 JSON → `400 Bad Request`。

2. **别用 `Invoke-RestMethod -Body $字符串` 传中文**
   中文会被编码破坏（服务器实际收到 `????`），规则匹配不到，
   结果"胸痛"也返回 `clarify`——**看上去像安全闸门失效，其实是消息没送对**。

> ✅ **唯一稳妥写法：JSON 转 UTF-8 字节数组，并且赋值和发送写在同一行**：
> ```powershell
> $bytes = [System.Text.Encoding]::UTF8.GetBytes('{"message":"这里写你的问题"}'); Invoke-RestMethod -Uri http://localhost:3000/ai/chat -Method POST -ContentType "application/json" -Body $bytes | ConvertTo-Json -Depth 5
> ```
>
> ### 🔴 必须写在同一行（分号分隔）——这是最容易踩的坑
>
> **千万不要把赋值和发送拆成两行复制**：
> ```powershell
> # ❌ 错误：拆两行会用到「上一条」的旧内容
> Invoke-RestMethod -Uri http://localhost:3000/ai/chat -Method POST -ContentType "application/json" -Body $bytes | ConvertTo-Json -Depth 5
> $bytes = [System.Text.Encoding]::UTF8.GetBytes('{"message":"脑卒中后想了解上肢摆放"}')
> ```
> 上面这段的实际执行结果是：**先拿上一条的 `$bytes`（可能还是"胸痛"）发出去**，
> 然后才赋新值。于是你会看到"明明问的是脑卒中，却返回 urgent(胸痛)"——
> 这不是后端坏了，是**发送内容还是上一条**。
>
> 另一个变体：PowerShell 显示 `>>` 续行提示符时，说明它认为命令没结束，同样会打乱顺序。
>
> ✅ **正确做法**：下面三条测试每条都是**一整行**，复制一行、粘贴、回车即可。

### 测试 ①：说"胸痛" → 应该报警

```powershell
$bytes = [System.Text.Encoding]::UTF8.GetBytes('{"message":"我刚才练着练着胸痛，还有点向左肩放射"}'); Invoke-RestMethod -Uri http://localhost:3000/ai/chat -Method POST -ContentType "application/json" -Body $bytes | ConvertTo-Json -Depth 5
```

**预期结果**（关键看这三处）：

```json
{
  "type": "urgent",          ← ① 类型是 urgent（紧急）
  "severity": 3,             ← ② 严重度 3（最高）
  "modelCalled": false,      ← ③ 没调用 AI（安全！）
  "message": "🚨 立即就医提示..."
}
```

> ✅ **`modelCalled: false` 是关键**——遇到危险情况时，系统根本不去问 AI，直接给固定安全提示。

### 测试 ②：正常提问 → 应该追问

```powershell
$bytes = [System.Text.Encoding]::UTF8.GetBytes('{"message":"脑卒中后想了解上肢摆放"}'); Invoke-RestMethod -Uri http://localhost:3000/ai/chat -Method POST -ContentType "application/json" -Body $bytes | ConvertTo-Json -Depth 5
```

**预期结果**：

```json
{
  "type": "clarify",
  "questions": [{
    "slot": "stage",
    "question": "请问当前处于什么阶段？",
    "options": [
      { "label": "2 周内或术后早期", "value": "acute" },
      { "label": "1-3 个月恢复中", "value": "subacute" },
      { "label": "3 个月以上", "value": "chronic" },
      { "label": "不清楚", "value": "unknown" }
    ]
  }]
}
```

### 测试 ③：说"没有胸痛" → 不应该报警

```powershell
$bytes = [System.Text.Encoding]::UTF8.GetBytes('{"message":"我最近没有胸痛，就是膝盖有点酸"}'); Invoke-RestMethod -Uri http://localhost:3000/ai/chat -Method POST -ContentType "application/json" -Body $bytes | ConvertTo-Json -Depth 5
```

**预期结果**：`"type": "clarify"`（**不是** urgent）

> ✅ 这条验证"否定句识别"。如果说"没有胸痛"也被报警，说明程序有问题。

### 1.4 验收标准（三条对照）

| 输入 | 期望 `type` | 期望 `modelCalled` | 说明 |
|---|---|---|---|
| 胸痛 / 呼吸困难 / 突发无力 | `urgent` | `false` | 危险，立即就医，不问 AI |
| 正常提问 | `clarify` | `false` | 信息不全，先追问 |
| "没有胸痛" | `clarify` | `false` | 否定句不误报 |

**三条全对 = 安全闸门工作正常。** 至此你已经验证了本项目最核心的功能，而且**完全没用到 Docker**。

### ⚠️ 排错：结果和上一条一模一样？

如果你发现"明明换了问题，返回的还是上一条的结果"（比如问脑卒中却返回胸痛的 urgent）：

**原因**：`$bytes` 赋值和发送没在同一行执行完，发送时用的还是**上一条的旧内容**。

**自检**：看 `message` 字段里匹配到的关键词是不是你这次问的。

| 你问的 | 返回里 `matched` 却是 | 说明 |
|---|---|---|
| 脑卒中 | `胸痛/心绞痛/胸部压榨感` | ❌ 发出去的是上一条"胸痛" |
| 脑卒中 | 无 `matched`、正常追问 | ✅ 正确 |

**解决**：严格复制**一整行**（含分号），一次粘贴、一次回车。见 1.3 开头的红色提醒。

# 路径 2：完整环境（Docker + 动作库，可选）

> 只有想看**动作库**（1324 条动作）时才需要这一步。
> 只做安全闸门验证的话，**不用往下看了**。

## 2.1 中国大陆网络：先配镜像加速 ★ 必做

### 为什么会失败

直接执行 `docker compose up` 大概率报：

```
failed to resolve reference "docker.io/pgvector/pgvector:pg16":
dialing registry-1.docker.io:443 ... connectex: 连接超时
（含 "Docker Desktop has no HTTPS proxy"）
```

这是 Docker Hub 在国内不可达，**不是你的配置问题**，反复重试没用。

### 方案 A：配置镜像加速器（推荐）

1. 打开 **Docker Desktop**
2. 右上角齿轮 **Settings** → 左侧 **Docker Engine**
3. 在 JSON 配置里加入 `registry-mirrors`（注意保持 JSON 格式正确，逗号别漏）：

```json
{
  "registry-mirrors": [
    "https://docker.xuanyuan.me",
    "https://docker.1ms.run",
    "https://docker.m.daocloud.io"
  ]
}
```

4. 点 **Apply & Restart**，等 Docker 重启完成（任务栏鲸鱼图标停止闪烁）

**验证是否生效**（任选一个源试）：

```powershell
docker pull docker.xuanyuan.me/pgvector/pgvector:pg16
```

能开始下载就说明配置成功。

#### 报错对照：看到这些说明什么

| 报错信息 | 含义 | 怎么办 |
|---|---|---|
| `dialing registry-1.docker.io:443 ... 连接超时`<br>（含 `has no HTTPS proxy`） | **加速源没生效**，还在直连 Docker Hub | 检查 JSON 配置格式（逗号别漏）→ Apply & Restart → 确认鲸鱼图标停闪 |
| `免费节点当前繁忙，请稍后重试`<br>（轩辕镜像返回） | ✅ **配置已生效**，但这个免费节点限流 | 换其他源试，或过一会儿重试 |
| `manifest unknown` / `not found` | 镜像名或 tag 写错 | 确认是 `pgvector/pgvector:pg16` |

> 💡 **「免费节点繁忙」其实是好消息** —— 说明你的 registry-mirrors 配对了、网络也通，
> 只是这个免费源当前限流。挨个换下面的源试：
>
> ```powershell
> docker pull docker.1ms.run/pgvector/pgvector:pg16
> docker pull docker.m.daocloud.io/pgvector/pgvector:pg16
> ```
>
> 也可以直接重跑 `docker compose up -d postgres`——配了多个 mirror 后，
> Docker 会按顺序尝试，一个失败会自动换下一个。

> ⚠️ **关于镜像源的三点提醒**
> 1. **源会失效 / 限流**。国内镜像源经常被封或限流，今天能用不代表明天能用；
>    免费节点尤其容易报"繁忙"，一个不行就换下一个。
> 2. **如果三个都失败**，说明这批源已失效，去搜"Docker 镜像加速器 2026"找当前可用的。
> 3. **仅限本地开发拉公共镜像**。生产环境、私有镜像一律不要走第三方加速源。

### 方案 B：有代理就填代理（更稳）

如果你有可用的 HTTP 代理：

**Docker Desktop** → **Settings** → **Resources** → **Proxies**
→ 勾选 **Manual proxy configuration** → 填你的 **HTTPS Proxy**（如 `http://127.0.0.1:7890`）
→ **Apply & Restart**

配完同样用上面的 `docker pull` 验证。

## 2.3 启动数据库

> ⚠️ **所有 docker 命令都带 `-f` 绝对路径**，这样无论你当前在哪个目录都能执行
> （`docker compose` 只在当前目录找 compose 文件，不指定就会报 "no configuration file provided"）。

```powershell
docker compose -f "D:\AI\R\rehab-motion-mvp\docker-compose.yml" up -d postgres
```

**首次会**：下载 PostgreSQL + pgvector 镜像，然后自动导入 1324 条动作数据（约 1-5 分钟）。

### 查看状态

```powershell
docker ps --filter "name=rehab-postgres"
```

**预期**：`STATUS` 显示 `Up (healthy)` 或 `Up xxx seconds (healthy)`。

## 2.4 验证动作库数据

```powershell
docker exec -it rehab-postgres psql -U rehab -d rehab_mvp -c "SELECT rehab_label, COUNT(*) FROM exercises GROUP BY rehab_label;"
```

**预期结果**：

```
   rehab_label    | count
------------------+-------
 REHAB_SAFE       |   378
 NEEDS_ASSESSMENT |   507
 NOT_RECOMMENDED  |   439
```

看到这三个数字 = 动作库导入成功。

### ❌ 如果查不到表（常见坑）

**原因**：`docker-entrypoint-initdb.d` 里的脚本**只在数据卷首次创建时执行**。
如果你之前起过容器（哪怕失败了），数据卷已存在，初始化脚本就不会再跑。

**解决**（会清空数据库数据，重新初始化）：

```powershell
docker compose -f "D:\AI\R\rehab-motion-mvp\docker-compose.yml" down -v
docker compose -f "D:\AI\R\rehab-motion-mvp\docker-compose.yml" up -d postgres
```

`-v` 会删除数据卷，下次启动重新执行初始化脚本。

## 2.5 数据库初始化说明

项目已自带初始化脚本（`infra\postgres\init\`）：

| 文件 | 作用 |
|---|---|
| `001_extensions_and_mvp.sql` | 建 pgvector / pg_trgm 扩展 + 术语表、知识块表、会话表 |
| `002_exercise_schema.sql` | 用 `\i` 引入动作库三个 SQL（建表 → 灌数据 → 建视图） |

动作库 SQL 来自本项目**外部**目录：

```
D:\AI\R\exercises-dataset-main\sql\
├── 01_schema.sql       -- 建 exercises 等三张表
├── 02_seed.sql         -- 1324 条动作 × 10 语言（16MB）
└── 03_rehab_filter.sql -- v_rehab_exercises 视图（硬排 rehab_level=3）
```

该目录通过 compose 挂载到容器 `/assets/exercise-sql`。
**如果 `D:\AI\R\exercises-dataset-main` 不存在，动作库会导入失败，但安全闸门不受影响。**

> 📌 **只测安全闸门可以完全跳过这一步** —— 安全闸门是纯函数，不查数据库。

# 常见问题

### Q1. `flutter: command not found`

Flutter 没进 PATH。用完整路径：

```powershell
D:\dev\flutter\bin\flutter.bat run -d chrome
```

### Q2. 前端显示"网络暂不可用"

1. 后端窗口还显示 `successfully started` 吗？

### Q3. Web 构建卡住 / 报网络错误

```
Failed to download .../flutter-web-sdk.zip
```

**解决**（按顺序）：

1. 重试 2-3 次（可能只是偶发）
2. 关掉 VPN / 代理
3. 设国内镜像（**国内最有效**），先执行这两行再重新运行：

```powershell
$env:PUB_HOSTED_URL="https://pub.flutter-io.cn"
$env:FLUTTER_STORAGE_BASE_URL="https://storage.flutter-io.cn"
cd D:\AI\R\rehab-motion-mvp\apps\mobile
flutter run -d chrome
```
