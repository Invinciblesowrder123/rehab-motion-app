# 路径 1：验证安全闸门（不需要 Docker / 数据库）

## 1.1 进入后端目录并启动

> ⚠️ PowerShell 打开后默认停在 `C:\Windows\system32`，**必须先 cd**，否则后面的命令都找不到文件。

```powershell
cd D:\AI\R\rehab-motion-mvp\apps\api
npm run start:dev
```

**首次启动**会编译 TypeScript（约 20-40 秒），出现下面这行才算成功：

```
[Nest] 12345  - LOG [NestApplication] Nest application successfully started
```

> `start:dev` 是**热重载模式**，改代码后自动重启。
> 想跑一次性版本：先 `npm run build`，再 `npm start`。
>
> **这个窗口不要关**，关了后端就停了。

### 可能的报错

| 报错 | 原因 / 处理 |
|---|---|
| `npm : 无法加载文件...禁止运行脚本` | PowerShell 执行策略限制。改用 `npm.cmd run start:dev` |
| `ENOENT: no such file or directory` | 没 cd 到 `apps\api`，重新执行上面的 cd |
| `Error: listen EADDRINUSE: address already in use :::3000` | 3000 端口被占。换端口：`$env:PORT=3001; npm run start:dev` |

## 1.2 确认后端活着

**新开一个 PowerShell 窗口**（原来的不要关）：

```powershell
Invoke-RestMethod -Uri http://localhost:3000/health | ConvertTo-Json
```

**预期结果**：

```json
{"status":"ok","service":"rehab-motion-api","safetyGate":"enabled","disclaimer":"本服务不提供医疗诊断，所有建议仅供参考。"}
```

看到 `"status":"ok"` 就说明后端正常。

> 💡 为什么不用 `curl`：PowerShell 里 `curl` 是 `Invoke-WebRequest` 的**别名**，
> 执行它会返回一堆表格（`StatusCode` / `Content` …），而不是上面这行 JSON，容易看懵。

## 1.3 三条 HTTP 测试（核心）

### ⚠️ Windows 必读：两个坑都在"发送端"

1. **别用 `curl -d '{"message":"..."}'`**
   PowerShell 的 `curl` 是 `Invoke-WebRequest` 别名，不认 `-H` / `-d`；
   就算改成 `curl.exe`，PowerShell 也会篡改内联 JSON 的双引号，服务器收到非法 JSON → `400 Bad Request`。

2. **别用 `Invoke-RestMethod -Body $字符串` 传中文**
   中文会被编码破坏（服务器实际收到 `????`），规则匹配不到，
   结果"胸痛"也返回 `clarify`——**看上去像安全闸门失效，其实是消息没送对**。

> ✅ **唯一稳妥写法：JSON 转 UTF-8 字节数组，并且赋值和发送写在同一行**：
> ```powershell
> $bytes = [System.Text.Encoding]::UTF8.GetBytes('{"message":"这里写你的问题"}'); Invoke-RestMethod -Uri http://localhost:3000/ai/chat -Method POST -ContentType "application/json" -Body $bytes | ConvertTo-Json -Depth 5
> ```
>
> ### 🔴 必须写在同一行（分号分隔）——这是最容易踩的坑
>
> **千万不要把赋值和发送拆成两行复制**：
> ```powershell
> # ❌ 错误：拆两行会用到「上一条」的旧内容
> Invoke-RestMethod -Uri http://localhost:3000/ai/chat -Method POST -ContentType "application/json" -Body $bytes | ConvertTo-Json -Depth 5
> $bytes = [System.Text.Encoding]::UTF8.GetBytes('{"message":"脑卒中后想了解上肢摆放"}')
> ```
> 上面这段的实际执行结果是：**先拿上一条的 `$bytes`（可能还是"胸痛"）发出去**，
> 然后才赋新值。于是你会看到"明明问的是脑卒中，却返回 urgent(胸痛)"——
> 这不是后端坏了，是**发送内容还是上一条**。
>
> 另一个变体：PowerShell 显示 `>>` 续行提示符时，说明它认为命令没结束，同样会打乱顺序。
>
> ✅ **正确做法**：下面三条测试每条都是**一整行**，复制一行、粘贴、回车即可。

### 测试 ①：说"胸痛" → 应该报警

```powershell
$bytes = [System.Text.Encoding]::UTF8.GetBytes('{"message":"我刚才练着练着胸痛，还有点向左肩放射"}'); Invoke-RestMethod -Uri http://localhost:3000/ai/chat -Method POST -ContentType "application/json" -Body $bytes | ConvertTo-Json -Depth 5
```

**预期结果**（关键看这三处）：

```json
{
  "type": "urgent",          ← ① 类型是 urgent（紧急）
  "severity": 3,             ← ② 严重度 3（最高）
  "modelCalled": false,      ← ③ 没调用 AI（安全！）
  "message": "🚨 立即就医提示..."
}
```

> ✅ **`modelCalled: false` 是关键**——遇到危险情况时，系统根本不去问 AI，直接给固定安全提示。

### 测试 ②：正常提问 → 应该追问

```powershell
$bytes = [System.Text.Encoding]::UTF8.GetBytes('{"message":"脑卒中后想了解上肢摆放"}'); Invoke-RestMethod -Uri http://localhost:3000/ai/chat -Method POST -ContentType "application/json" -Body $bytes | ConvertTo-Json -Depth 5
```

**预期结果**：

```json
{
  "type": "clarify",
  "questions": [{
    "slot": "stage",
    "question": "请问当前处于什么阶段？",
    "options": [
      { "label": "2 周内或术后早期", "value": "acute" },
      { "label": "1-3 个月恢复中", "value": "subacute" },
      { "label": "3 个月以上", "value": "chronic" },
      { "label": "不清楚", "value": "unknown" }
    ]
  }]
}
```

### 测试 ③：说"没有胸痛" → 不应该报警

```powershell
$bytes = [System.Text.Encoding]::UTF8.GetBytes('{"message":"我最近没有胸痛，就是膝盖有点酸"}'); Invoke-RestMethod -Uri http://localhost:3000/ai/chat -Method POST -ContentType "application/json" -Body $bytes | ConvertTo-Json -Depth 5
```

**预期结果**：`"type": "clarify"`（**不是** urgent）

> ✅ 这条验证"否定句识别"。如果说"没有胸痛"也被报警，说明程序有问题。

### 1.4 验收标准（三条对照）

| 输入 | 期望 `type` | 期望 `modelCalled` | 说明 |
|---|---|---|---|
| 胸痛 / 呼吸困难 / 突发无力 | `urgent` | `false` | 危险，立即就医，不问 AI |
| 正常提问 | `clarify` | `false` | 信息不全，先追问 |
| "没有胸痛" | `clarify` | `false` | 否定句不误报 |

**三条全对 = 安全闸门工作正常。** 至此你已经验证了本项目最核心的功能，而且**完全没用到 Docker**。

### ⚠️ 排错：结果和上一条一模一样？

如果你发现"明明换了问题，返回的还是上一条的结果"（比如问脑卒中却返回胸痛的 urgent）：

**原因**：`$bytes` 赋值和发送没在同一行执行完，发送时用的还是**上一条的旧内容**。

**自检**：看 `message` 字段里匹配到的关键词是不是你这次问的。

| 你问的 | 返回里 `matched` 却是 | 说明 |
|---|---|---|
| 脑卒中 | `胸痛/心绞痛/胸部压榨感` | ❌ 发出去的是上一条"胸痛" |
| 脑卒中 | 无 `matched`、正常追问 | ✅ 正确 |

**解决**：严格复制**一整行**（含分号），一次粘贴、一次回车。见 1.3 开头的红色提醒。

## 2.1 配置 Docker 网络（国内必做）

### 为什么会失败

直接执行 `docker compose up` 大概率报：

```
failed to resolve reference "docker.io/pgvector/pgvector:pg16":
dialing registry-1.docker.io:443 ... connectex: 连接超时
（含 "Docker Desktop has no HTTPS proxy"）
```

Docker Hub 在国内不可达，**不是你的配置问题**，反复重试没用。
下面两种方案选一种——**首推方案 A（代理）**，更稳且永远有效。

---

### 方案 A：给 Docker Desktop 配代理（首推）

> ⭐ **即使你系统代理（Clash / v2rayN 等）已经开了，Docker 也不会自动用它**。
> 因为 Docker Desktop 的引擎跑在 WSL2 虚拟机里，**不读 Windows 系统代理**——
> 必须在 Docker Desktop 自己的设置里单独配。

假设你用 Clash for Windows（其它工具同理），端口默认 **7890**：

**步骤**：

1. 打开 **Docker Desktop**（任务栏鲸鱼图标右键 → Settings）
2. 左侧菜单点 **Resources** → 切到 **Proxies** 标签
3. 勾选 **Manual proxy configuration**
4. **Web Server (HTTPS)** 填 `http://127.0.0.1:7890`（端口与你的代理软件一致）
5. **Bypass** 留空（或者填 `127.0.0.1,localhost` 防止本地请求也走代理）
6. 点 **Apply & Restart**，等 Docker 重启完成（鲸鱼图标停止闪烁）

**验证（直连 Docker Hub，不加镜像加速前缀）**：

```powershell
docker pull pgvector/pgvector:pg16
```

能看到下载进度条（几 MB 到几十 MB 不等，取决于代理带宽）就说明配置成功。
下载完的镜像本地缓存，下次 `docker compose up` 直接用。

> 💡 **Allow LAN（Clash 上的开关）不用开**。Docker 走的是 `127.0.0.1:7890` 本机回环地址，
> 跟"是否允许局域网设备用我的代理"无关。

#### 排错：配了还是连不上

| 现象 | 原因 / 处理 |
|---|---|
| 走代理后 `docker pull` 仍报 `连接超时` | 端口填错。Clash 默认 7890，但如果你改过端口或用其他工具（v2rayN 常是 10809，Clash Verge 常用 7890），按你的实际端口填 |
| 报 `proxyconnect tcp: dial tcp 127.0.0.1:7890: connectex: refused` | 代理软件没启动，或 Allow LAN 关着（**本机回环 127.0.0.1 不需要开 Allow LAN**，确保代理软件本身开着就行） |
| 报 `407 Proxy Authentication Required` | 代理开了认证。在 URL 里带用户名密码：`http://用户名:密码@127.0.0.1:7890` |
| 报 `TLS handshake timeout` | 代理的 TLS 代理配置有问题。试着把 Web Server (HTTP) 也填同一地址，或换 HTTP 代理节点 |

---

### 方案 B：配置镜像加速器（无代理时的备选）

> 仅当方案 A 没有代理可用时用。
> 镜像源经常限流 / 失效，比代理方案不稳定得多。

**步骤**：

1. **Docker Desktop** → **Settings** → **Docker Engine**
2. 在 JSON 配置里加入 `registry-mirrors`（保持 JSON 格式正确，逗号别漏）：

```json
{
  "registry-mirrors": [
    "https://docker.xuanyuan.me",
    "https://docker.1ms.run",
    "https://docker.m.daocloud.io"
  ]
}
```

3. **Apply & Restart**，等 Docker 重启完成

**验证**（任选一个源试）：

```powershell
docker pull docker.xuanyuan.me/pgvector/pgvector:pg16
```

#### 报错对照

| 报错 | 含义 | 处理 |
|---|---|---|
| `dialing registry-1.docker.io:443 ... 连接超时` | **加速源没生效**，还在直连 | 检查 JSON 格式 → Apply & Restart → 确认鲸鱼图标停闪 |
| `免费节点当前繁忙，请稍后重试`（轩辕） | ✅ 配置已生效，但这个免费节点限流 | 换其他源或稍后重试 |
| `manifest unknown` / `not found` | 镜像名或 tag 错 | 确认是 `pgvector/pgvector:pg16` |

> 也可以直接重跑 `docker compose up -d postgres`——配多个 mirror 后 Docker 会按顺序 failover。

> ⚠️ **源会失效 / 限流**。今天能用不代表明天能用；如果三个都失败，去搜"Docker 镜像加速器 2026"找当前可用的。
> ⚠️ **仅限本地开发拉公共镜像**。生产环境、私有镜像不要走第三方加速源。

## 2.3 启动数据库

> ⚠️ **所有 docker 命令都带 `-f` 绝对路径**，这样无论你当前在哪个目录都能执行
> （`docker compose` 只在当前目录找 compose 文件，不指定就会报 "no configuration file provided"）。

```powershell
docker compose -f "D:\AI\R\rehab-motion-mvp\docker-compose.yml" up -d postgres
```

**首次会**：下载 PostgreSQL + pgvector 镜像，然后自动导入 1324 条动作数据（约 1-5 分钟）。

### 查看状态

```powershell
docker ps --filter "name=rehab-postgres"
```

**预期**：`STATUS` 显示 `Up (healthy)` 或 `Up xxx seconds (healthy)`。

## 2.4 验证动作库数据

```powershell
docker exec -it rehab-postgres psql -U rehab -d rehab_mvp -c "SELECT rehab_label, COUNT(*) FROM exercises GROUP BY rehab_label;"
```

**预期结果**：

```
   rehab_label    | count
------------------+-------
 REHAB_SAFE       |   378
 NEEDS_ASSESSMENT |   507
 NOT_RECOMMENDED  |   439
```

看到这三个数字 = 动作库导入成功。

### ❌ 如果查不到表（常见坑）

**原因**：`docker-entrypoint-initdb.d` 里的脚本**只在数据卷首次创建时执行**。
如果你之前起过容器（哪怕失败了），数据卷已存在，初始化脚本就不会再跑。

**解决**（会清空数据库数据，重新初始化）：

```powershell
docker compose -f "D:\AI\R\rehab-motion-mvp\docker-compose.yml" down -v
docker compose -f "D:\AI\R\rehab-motion-mvp\docker-compose.yml" up -d postgres
```

`-v` 会删除数据卷，下次启动重新执行初始化脚本。

**如果 `D:\AI\R\exercises-dataset-main` 不存在，动作库会导入失败，但安全闸门不受影响。**

# 启动前端界面

> 前置：路径 1 的后端必须还在运行。
>
> 💡 **想让动作库有数据**，后端需要读到 `DATABASE_URL`。项目已在 `.env` 里配好，
> 启动 API 时会自动加载（见 2.2）。如果没建 `.env`，动作库页面会显示"暂不可用"。

| 方式 | 需要什么 | 说明 |
|---|---|---|
| **A. 网页版** | Chrome（已装 ✅） | 首次需下载 ~100MB Web SDK |
| **B. 安卓真机** | 安卓手机 + 数据线 | 最可靠，不依赖大文件下载 |
| **C. 安卓模拟器** | Android Studio 建 AVD | 需下载 ~1GB 系统镜像 |

### 方式 A：网页版

> ⭐ **推荐用 A-2（web-server）**。A-1（`-d chrome`）经常因为 Chrome 已在运行、
> 或以管理员身份启动等原因失败，报 `Failed to launch browser after 3 tries`。

#### A-1：让 Flutter 自动打开 Chrome

```powershell
cd D:\AI\R\rehab-motion-mvp\apps\mobile
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:3000
```

#### A-2：只起服务，自己开浏览器（更稳 ★ 推荐）

```powershell
cd D:\AI\R\rehab-motion-mvp\apps\mobile
flutter run -d web-server --web-port=8080 --dart-define=API_BASE_URL=http://localhost:3000
```

看到下面这行就成功了：

```
Flutter web server running on http://localhost:8080
```

然后**自己打开浏览器**访问 <http://localhost:8080> 即可。

> ✅ 这种方式同样支持**热重载**（在窗口按 `r`），F12 调试也一样能用——
> 因为你用的是真实浏览器，只是换了个启动方式。

#### 报错：`Failed to launch browser after 3 tries`

```
Failed to launch browser after 3 tries. Command used to launch it: C:\Program Files\Google\Chrome\Application\chrome.exe
Failed to launch browser. Make sure you are using an up-to-date Chrome or Edge.
Otherwise, consider using -d web-server instead
```

**按顺序试**：

1. **直接用 A-2（`-d web-server`）**——最简单，绕开所有 Chrome 启动问题
2. 或者**彻底关掉所有 Chrome 窗口**（包括后台托盘）再试 A-1
   —— Chrome 已在运行时，Flutter 用新的 `--user-data-dir` 启动新实例常失败
3. 或者换 Edge：`flutter run -d edge --dart-define=API_BASE_URL=http://localhost:3000`

> 如果卡在 Web SDK 下载，见常见问题 Q3（含国内镜像配置）。

### 方式 B：安卓真机

1. 手机「设置 → 关于手机」连点「版本号」7 次 → 开发者模式
2. 打开「USB 调试」，数据线连电脑，手机上点「允许」
3. 查电脑 IP：`ipconfig` 找「IPv4 地址」
4. 执行（把 IP 换成你的）：

```powershell

flutter run --dart-define=API_BASE_URL=http://192.168.1.100:3000
```

> ⚠️ 真机**不能**用 `localhost`，必须用电脑局域网 IP。

### 方式 C：安卓模拟器

1. 打开 Android Studio → **Device Manager** → **Create Device**
2. 选手机型号 → 下载系统镜像（推荐 API 34）
3. 启动模拟器后：

```powershell
cd D:\AI\R\rehab-motion-mvp\apps\mobile
```

# 常见问题

### Q1. `flutter: command not found`

Flutter 没进 PATH。用完整路径：

```powershell
D:\dev\flutter\bin\flutter.bat run -d chrome
```

### Q2. 前端显示"网络暂不可用"

1. 后端窗口还显示 `successfully started` 吗？
2. 执行 `Invoke-RestMethod -Uri http://localhost:3000/health | ConvertTo-Json`，通不通？
3. `API_BASE_URL` 对不对？网页版/模拟器 `localhost:3000`；真机 `<电脑IP>:3000`

### Q3. Web 构建卡住 / 报网络错误

```
Failed to download .../flutter-web-sdk.zip
```

**解决**（按顺序）：

1. 重试 2-3 次（可能只是偶发）
2. 关掉 VPN / 代理
3. 设国内镜像（**国内最有效**），先执行这两行再重新运行：

```powershell
$env:PUB_HOSTED_URL="https://pub.flutter-io.cn"
$env:FLUTTER_STORAGE_BASE_URL="https://storage.flutter-io.cn"
cd D:\AI\R\rehab-motion-mvp\apps\mobile
flutter run -d chrome
```

4. 换网络（手机热点）
5. 实在不行 → 用**安卓真机**，不需要 Web SDK

> 上面两个镜像变量只在当前窗口有效，换窗口要重设。

### Q4. `docker compose` 报 "no configuration file provided"

没带 `-f`。所有命令都用绝对路径：

```powershell
docker compose -f "D:\AI\R\rehab-motion-mvp\docker-compose.yml" up -d postgres
```

### Q5. `docker pull` 超时 / Docker Hub 不可达

见 **2.1 给 Docker Desktop 配代理 / 镜像加速**。国内直连 Docker Hub 失败是常态。

### Q6. 改了代码但界面没变

`flutter run` 窗口按 `r`（热重载）→ 不行按 `R`（重启）→ 再不行 `q` 退出重跑。

### Q7. 后端报数据库连接错误

```
ERROR [TypeOrmModule] Unable to connect to the database
```

**这是正常的**。安全闸门不依赖数据库，即使报这个错，`/ai/chat` 照样工作（路径 1 已验证）。
只有查动作库才需要数据库。

### Q8. 数据库起来了，动作库还是"暂不可用"

**排查顺序**：

1. **有 `.env` 吗？** 本地跑 API 需要它提供 `DATABASE_URL`：
   ```powershell
   Test-Path D:\AI\R\rehab-motion-mvp\.env
   ```
   显示 `False` 就执行 2.2 的 `Copy-Item` 建一个。

2. **改完 .env 重启后端了吗？** 环境变量只在启动时读取，
   在 `npm run start:dev` 窗口 `Ctrl+C` 后重新启动。

3. **数据库容器活着吗？**
   ```powershell
   docker ps --filter "name=rehab-postgres"
   ```
   应显示 `Up ... (healthy)`。

4. **直接测端点**（把 3000 换成你的端口）：
   ```powershell
   Invoke-RestMethod -Uri "http://localhost:3000/exercises?limit=3" | ConvertTo-Json -Depth 5
   ```
   返回动作列表 = 正常；返回 `503 数据库未配置` = 第 1、2 步没做。

### Q9. 动作名称显示英文，不是中文

**这是已知的数据问题，不是 bug。**

动作库 `exercises` 表的 `name_zh` 列**没有真正填充中文**——它和 `name_en` 内容完全一样
（1324 条里只有 6 条含中文）。所以 App 里看到的是英文名。

中文动作名其实在另一份资产里：`D:\AI\R\exercises-dataset-main\rehab\exercises_manual_zh.md`。
后续要修就得从那里提取中文名回填数据库。**不影响安全闸门和动作库筛选功能。**
